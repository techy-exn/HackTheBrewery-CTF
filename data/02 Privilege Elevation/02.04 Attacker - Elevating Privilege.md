### Some important infomation

In the previous exercice we have seen that we are **local adminiatrator** and **which privileges** belongs to this account. The goal we want now is to have enough privileges to **steal the token of a process** belonging to the **Domain Administrator**.

<div class="info">
	
A **Windows access** token is an operating-system object that represents a **security identity** + its **permissions**. In practice, it’s the thing Windows attaches to a running process (and its threads) to decide what that code is allowed to do.
What a token answers
When a process tries to do something like read a file, open a registry key, talk to a service, access a network share, Windows checks the token to answer:
	
* **Who** are you? (the user account / Security Identifier, or SID)
* What **groups** are you in? (e.g., Domain Users, Local Administrators, Domain Admins)
* What **special privileges** do you have? (e.g., “can debug other processes,” “can load drivers,” etc.)
* What **restrictions** apply? (integrity level, whether it’s elevated, whether it’s constrained)

### Elevating privilege in Windows 7

In Windows 7 we will be bypassing **UAC** (User Account Control).
Why is this needed? When a user is in the administrator group, windows gives them 2 tokens at logon:
* Filtered (**Medium** integrity) token
* Full (**High** integrity) token

By default, processes run with the filtered medium token. This is why you often get the screen “run as administrator”
Whenever you do this, Windows:
* **Switches** to the **full token**
* Creates a new **elevated process**
* That process runs at **High integrity**

So UAC is basically a **token filter** and consent boundary.

Now we will **bypass** this and **abuse** a **trusted auto-elevating** mechanism. To do this we will use the following command: 
	
```
uacbybass sspi C:\users\admin\Downloads\w7hacked.exe 
```

![UAC Bypass](/images/Inside_Beacon_UACBypass.jpg)

The bypass tricks Windows into:
* **Believing a legitimate system** component is being launched
* **Triggering auto-elevation**
* Launching your supplied executable **in the elevated context**

We will now be using the second beacon with full admin token.

![After UAC Bypass](/images/Adaptix_SecondBeacon_AfterUAC.jpg)
	
Again verify by using whoami

### Stealing the token

Now we have all the right privileges that we need. Next step is to **steal the token** of a **process** from the **domain administrator**. Once we have this, we can start moving laterally **towards** the domain controller.

To be able to see this, we need to right-click on our beacon and select *browsers > process browser*

![Process Browser](/images/RightClickBeacon_ProcessBrowser.jpg)
	
You will see that the process browser at first is blank. Within the client you need to **click the refresh** button to be able to see all the processes

![Refresh Process Browser](/images/AdaptixInsideBeacon_RefreshProcessBrowser.jpg)
	
Scroll through the processes and find one with the **domain admin account**. (the domain admin account was engineeringadmin)

*Right click* this process and click *steal token*. With this we will steal the token of the domain admin and it will look like we are the domain admin.

![Steal token Eng Admin](/images/RightClick_StealToken_EngAdmin.jpg)
	
If you head back to the console, you will see a **BOF** has been used (you could also do *token steal PID* command in the console).

Always verify

Recap:
1. Started as **Local Admin** (Medium Integrity) → running with a **filtered UAC token**
2. Used **elevation** → obtained **High Integrity** (full admin token)
3. A Domain Admin token was present on the machine (active logon session)
4. With sufficient **local privileges**, that **token** could be **impersonated**
5. Now we have **stolen the token** of the **domain admin**!
