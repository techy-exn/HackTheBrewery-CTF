### prerequisite

Since we are using Cloudshare, the machines will always be turned off and all the processes will be killed. In a real environment this is not the case. To be able to successfully finish this task, please **switch user** and login with the domain admin account `it-admin`.

**!!It’s very important you switch user and don’t logout or restart the computer!!**

The password can be found in the <a href="/credentials" target="_blank">**credentials**</a> page of the CTFd.
Once logged in, open some **applications** like notepad, calculator or sticky notes (or anything else). We just need this account to start a **process**.

<div class="attacker-container">
<div class="attacker-label">Gaining system privilege W10</div>

In the last exercise we created a beacon on our IT workstation, which is a Windows 10.

We need to gain more privileges if we want to gain the context of our admin. However there is 1 big difference, before it was a Windows 7 and now it's a Windows 10 so we have to change our attack a little bit. The UAC Bypass won't really work here but we do have another option. Within AdaptixC2 there is also the getsystem token command. With this command we will also have enough priviliges to steal the admin token.

	
Open the beacon of the IT workstation and use 

```
getsystem token
```
	
![getsystem token](/images/GetSystemToken_W10.jpg)

<div class="info">
	
Getsystem token is a command that attempts to **elevate privileges** to **NT AUTHORITY\SYSTEM** (the **highest level** on Windows) by obtaining and using a **SYSTEM** security token.
	
In practice, this lets the agent run commands with **full control** over the machine, **beyond normal admin** rights.
</div>
	
</div>

<div class="attacker-container">
<div class="attacker-label">Lateral Movement to IT DC</div>

Now we have system context, we're going to drop our last beacon on the IT Domain Controller to get access.
There is a beacon created for this domain controller. 

**Drop beacon**: 
`jump psexec DC-IT-01 /home/sysadmin/AdaptixProjects/ShadowHackers/DCIThacked.exe -n test -d test`

![Failed connection](/images/Jump_PSExec_Failed.jpg)

<div class="info">
	
We will see that this failed because we have the wrong context. We have system level privileges over this computer but we don't have access to the share.

However with system level priviliges, we can steal the token of the it-admin and that user will have access to the share.

</div>

</div>

<div class="attacker-container">
<div class="attacker-label">Stealing admin token</div>

Let's steal the token of the admin so we can get his context. Right click on the beacon and choose the process browser. Click the refresh button to see all the processes and when you've done the prerequisite at the top of the challange, there will be a process launched with the `it-admin` context (if it's not there, please look at the beginning of this challange where you need to open a process as it-admin). Right click on this and steal token. Or go the console and type

```
steal token PID
```

![getsystem token](/images/StealToken_it-admin.jpg)
	
![it admin context](/images/it-admin-context.jpg)
